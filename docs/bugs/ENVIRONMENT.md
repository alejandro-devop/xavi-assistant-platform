# Environment — what an agent cannot deduce from the code

This file belongs to **this** project. Agents read it before touching the
browser, and it exists to cut the most expensive waste of all: an agent trying
made-up addresses, mounting an environment that was already up, or chasing one
that isn't there.

When something here stops being true, fix it. An outdated map does more damage
than no map.

## What must NOT be run

- `docker compose down` / `docker stop` anywhere — services are the user's.
- **Anything touching containers not named `xavi-assistant-*`.** This machine
  is shared: the `ai_*` containers (another n8n stack on port 5678, currently
  stopped) and the `yamaha-*` containers belong to other work. Never start,
  stop, or inspect their data.
- `pnpm format:fix` on files you didn't touch — it rewrites half the repo's
  markdown and pollutes the diff.

## How to get real data

- n8n workflows (no editor login needed):
  `docker exec xavi-assistant-n8n-1 n8n list:workflow`
- The one working webhook (verified):
  `curl -s -X POST http://localhost:5679/webhook/ping -H 'content-type: application/json' -d '{"text":"hi"}'`
  → `{"ok":true,"reply":"pong","receivedText":"hi",...}`
- Ollama models: `curl -s http://localhost:11434/api/tags` (currently `qwen2.5:7b`)

## Gotchas of this repository

- **Two n8n stacks can exist on this host.** Xavi's runs on **5679**
  (localhost-only, compose project `xavi-assistant`); port 5678 belongs to an
  unrelated stack (`~/ai-stack`, other user's data, currently stopped). If you
  see 5678 answering, it is NOT xavi's n8n.
- **n8n workflow imports silently skip webhook registration** if the webhook
  node lacks a `webhookId` field, and imports arrive deactivated: activate with
  `n8n update:workflow --id=<id> --active=true` and the container needs a
  restart (by the user) to register production URLs.
- **Ollama exists twice on this machine**: the native one on 11434 (ours) and a
  containerized `ai_ollama` from the other stack (not ours, no published
  ports). Always use `localhost:11434`; from inside n8n use
  `http://host.docker.internal:11434`.
- Secrets live only in `infra/.env` (gitignored). The repo is public: never
  write a real hostname token or credential into a tracked file — gitleaks runs
  in CI and there's a pre-commit hook (`.githooks/`).
